# Second Brain (agy-lab4-second-brain)

Локальний персональний **Second Brain** — система зовнішньої пам’яті для навчальних нотаток.
Нотатки зберігаються як Markdown-файли з YAML frontmatter і класифікуються за адаптованою моделлю **PARA**
(Projects, Areas, Resources, Archives) плюс каталог **Inbox** для нових записів.
Лабораторна робота №4 з дисципліни «Архітектура спеціалізованих комп’ютерних систем».

## Можливості
- перегляд списку нотаток, категорій (Inbox/Projects/Areas/Resources/Archives), статусів і тегів;
- пошук за словами (назва, теги, текст; без урахування регістру, кирилиця підтримується);
- фільтр за тегом, який комбінується з пошуком;
- вікі-посилання `[[Назва нотатки]]` і `[[Назва|текст]]`, перехід за ними, позначення битих посилань, зворотні посилання;
- створення та редагування нотаток; «видалення» замінено архівуванням (файл переноситься до `Archives/`);
- повністю локальна робота: без зовнішніх API, без залежностей від npm-пакетів.

## Швидкий старт
Потрібен лише **Node.js 18+** (перевірити: `node -v`).

```bash
npm start            # http://localhost:3000
npm test             # автотести (вбудований test runner Node.js)
npm run validate     # перевірка бази нотаток (поля, значення, биті посилання)
```

Налаштування через змінні середовища: `PORT` (за замовчуванням 3000), `NOTES_DIR` (за замовчуванням `./notes`).

## Модель нотатки
```markdown
---
title: "Назва нотатки"
created: 2026-11-10
updated: 2026-11-10
type: resource        # resource | project | area | moc | idea | draft
status: active        # inbox | active | archived
tags: [architecture, cloud]
source: "власний конспект"
---
```
Шаблон — у `templates/note-template.md`.

## API (локальний)
| Метод і шлях | Призначення |
|--------------|-------------|
| `GET /api/notes?q=&tag=&category=&status=&type=` | список із пошуком і фільтрами |
| `GET /api/notes/<Категорія>/<Назва>` | нотатка з HTML, посиланнями та зворотними посиланнями |
| `POST /api/notes` | створити (`title`, `category`, `type`, `status`, `tags`, `body`) |
| `PUT /api/notes/<id>` | оновити теги, статус, тип і текст (назва незмінна) |
| `POST /api/notes/<id>/archive` | перенести до `Archives/` зі статусом `archived` |
| `GET /api/tags`, `GET /api/categories`, `GET /api/meta` | довідкові дані |

## Архітектура коротко
Вебінтерфейс (`src/public`) → HTTP-сервер (`src/server.js`) → сховище (`src/notes.js`) → файли `.md`.
Докладніше — у [docs/architecture.md](docs/architecture.md): компоненти, потоки даних, критерії приймання, ризики та порівняння локальної й хмарної версій.

## Політика приватності та безпеки
- Нотатки лежать лише на вашому диску; застосунок не звертається до інтернету.
- Сервер слухає тільки `127.0.0.1`, перевіряє заголовок `Host`, приймає запис лише як `application/json`, не вмикає CORS.
- Увесь HTML із нотаток екранується; посилання `javascript:` відкидаються; діє CSP `default-src 'self'`.
- **Не додавайте** до нотаток паролі, токени, ключі, медичні та фінансові дані. Файли `.env`, `*.key`, `*.pem` у `.gitignore`.
- Git не є резервною копією: тримайте ще одну копію на іншому носії (правило 3-2-1).

## Agent Skill
`.agents/skills/second-brain/SKILL.md` — workspace-навичка для AI-агента Google Antigravity: класифікує нотатки за PARA, пропонує теги й вікі-посилання, **не вигадує джерела, не видаляє й не переміщує файли без підтвердження** та завершує роботу журналом запропонованих змін.

## Обмеження
- Індекс перебудовується при кожному запиті (достатньо для сотень нотаток; для тисяч потрібен кеш).
- Назву нотатки змінити не можна (посилання прив’язані до назви); перейменування — вручну разом із посиланнями, потім `npm run validate`.
- Мінімальний рендерер Markdown: без таблиць, зображень і вкладених списків.
- Один користувач, без автентифікації та одночасного редагування.
